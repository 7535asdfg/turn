# Pic2Mesh · 照片生成可旋转的 3D 模型

纯浏览器实现的照片三维重建网页应用，包含两种模式：

| 模式 | 输入 | 算法 | 输出 |
| --- | --- | --- | --- |
| **单张照片** | 1 张图片 | Depth Anything V2 单目深度估计 → 2.5D 网格 | 带纹理的浮雕式 3D 效果图 |
| **多角度重建** | 12–36 张环绕照片 | **SfM + MVS**（参考 COLMAP 流程） | 相机位姿、稀疏点云、稠密三角网格 |

所有推理与计算都在浏览器本地完成，照片不会上传到任何服务器。
多角度模式不需要安装 COLMAP、OpenCV、Python 服务或任何本地依赖。

---

## 一、快速开始

**方式 1（推荐）**：双击 `start.bat`，它会启动本地 HTTP 服务并打开
<http://localhost:8000/index.html>。

**方式 2**：在项目目录执行

```bash
python -m http.server 8000
```

然后浏览器访问 <http://localhost:8000/index.html>。

> 多角度模式使用 ES Module（`js/core/*.js`），必须通过 HTTP 打开；
> 直接双击 `index.html`（`file://`）时浏览器会阻止模块加载。
> 单张模式在 `file://` 下也可能因 WebGPU / 本地模型读取限制而回退在线下载，建议始终用 `start.bat`。

浏览器要求：Chrome / Edge 等现代浏览器；单张模式优先使用 WebGPU，不支持时回退 WASM。

## 二、项目结构

```
项目/
├── index.html              网页 UI + Three.js 渲染 + 单图深度重建
├── start.bat               Windows 一键启动本地服务
├── package.json            仅用于 Node 测试（"type": "module"），网页不需要

│   ├── image.js            RGBA 缩放、灰度、Census、EXIF 焦距解析
│   ├── orb.js              ORB 特征提取（FAST + Harris + 旋转 BRIEF）与匹配
│   ├── geometry.js         本质矩阵 RANSAC、位姿恢复、三角化、PnP、位姿/点 LM
│   ├── sfm.js              增量式 SfM：匹配 → 轨迹 → 初始像对 → PnP 定位 → BA
│   └── mvs.js              稠密 MVS：平面扫描 → 左右一致性 → TSDF → Marching Tetrahedra

├── server/                 旧版 TripoSR 服务残留，网页不再使用，可删除
└── tests/                  合成数据与数值/浏览器端到端测试
```

## 三、多角度模式使用说明

1. 顶部切换到 **「多角度重建」**。
2. 点击或拖入 **同一物体** 的多张照片（支持多选、拖拽、粘贴）。
   建议 **12–36 张**，相邻照片重叠 **70% 以上**，围绕物体转一圈。
3. 点击 **「开始多角度重建」**。
4. 状态区会依次显示：
   - 特征提取 / 图像对匹配 / 相机定位 / 光束法平差（SfM）
   - 平面扫描深度图 / 左右一致性检查 / TSDF 融合 / 网格提取（MVS）
5. 完成后可以：
   - 鼠标拖拽旋转、滚轮缩放、右键平移；
   - 切换 **线框 / 点云 / 原色（无光照）**；
   - 在参数区切换 **显示相机视锥 / 显示稀疏点云**；
   - **导出 GLB**（包含顶点颜色的三角网格）。

### 拍摄建议

- 手机/相机保持 **同一焦距**（不要中途变焦），关闭美颜/人像虚化。
- 光线均匀，避免强烈反光、透明或纯白/纯黑无纹理表面。
- 物体尽量占画面 40% 以上；背景有纹理更好，但不要有大量重复图案。
- 按顺序拍摄（文件名排序后会保持顺序）；相邻照片不要跳拍太远。
- 运动模糊、失焦会显著降低匹配成功率。

### 参数

| 参数 | 说明 |
| --- | --- |
| 匹配窗口 | 每张照片与前后 N 张匹配。顺序拍摄时 2–4 足够；无序照片可调大 |
| 稠密重建精度 | 快速（体素 112，预览）/ 标准（128）/ 精细（160）。精度越高越慢 |
| 生成稠密网格 | 取消后只运行 SfM，输出相机与稀疏点云 |
| 显示相机 / 稀疏点 | 可视化开关，不影响重建结果 |

## 四、算法说明

### 4.1 SfM（Structure-from-Motion）

参考 COLMAP 的增量式重建流程，全部用 JavaScript 实现：

```
图像
 └─ ORB 特征：FAST-9 角点 → Harris 评分与 NMS → 金字塔分配
               → 灰度质心方向 → 旋转 BRIEF-256 描述子
 └─ 特征匹配：Hamming 距离 + Lowe 比值 + 双向交叉验证
 └─ 几何验证：归一化 8 点法本质矩阵 RANSAC
               （分层采样 12 点、双随机种子取最优）
 └─ 特征轨迹：并查集合并匹配；同一张图的多个候选观测保留，
               三角化时用一致性组合挑选正确观测
 └─ 初始像对：选择三角化点数最多、基线/夹角足够的像对
 └─ 增量定位：
       · PnP RANSAC（6 点 DLT）
       · 两视图相对位姿 + 基线尺度 λ 解析投票（强约束）
       · 多邻居“相机中心射线交会”（消除平面镜面歧义）
       · 注册前与最强像对的旋转/基线方向一致性校验
 └─ 三角化新轨迹 → 相机/三维点交替 LM 优化（近似 bundle adjustment）
 └─ 相机一致性剪枝：观测点过少或重投影误差异常偏大的相机剔除
```

输出的相机位姿在任意尺度的 SfM 世界坐标系中；稀疏点云带 RGB 颜色。

### 4.2 MVS（Multi-View Stereo）

```
每个参考视图（快速 10 / 标准 16 / 精细 24 个）
 └─ 选邻域视图（共享稀疏点最多 + 视角差 < 72°）
 └─ 平面扫描（inverse depth 采样）
       · Census 5×5 + 灰度差光度代价
       · 多个邻域视图取最小的两个代价平均（抗遮挡）
       · 抛物线亚像素深度精化 + 3×3 中值滤波
 └─ 左右一致性：把深度点投影到最优邻域，比较深度差（>6% 剔除）
 └─ TSDF 融合：
       · 从稀疏点鲁棒包围盒建立等距体素场
       · 窄带内加权平均 TSDF 与颜色
       · 未观测体素由多视图前/后投票决定内外
       · 已知体素掩码向外膨胀 1–3 层（随精度），闭合深度图的小空洞
 └─ Marching Tetrahedra 提取三角网格（6 四面体/立方体，顶点焊接）
 └─ 一次 Laplacian 平滑 + 逐顶点法线 + 顶点颜色
```

### 4.3 坐标与导出

- SfM 世界的尺度是任意的（初始像对基线归一化为 1）。
- 相机视锥、稀疏点、稠密网格都在同一坐标系中显示。
- 导出 GLB 时保留顶点颜色；由于网格使用顶点色而非纹理图，
  导入 Blender 后可在材质中看到颜色，但不会生成 UV 贴图。
- 视图自动取景/重置只影响相机，不改变模型坐标。

## 五、性能与限制

- **耗时**（Node 基准，浏览器相近）：
  - 36 张 480×360 合成图：SfM 约 6–8 s，标准 MVS 约 7 s；
  - 建议真实照片长边先缩放到 720 px（网页会自动缩放）。
- **内存**：总像素量随照片数量线性增长；40 张为上限。
- **成功率取决于照片**：多角度重建要求同一物体、足够重叠、纹理丰富。
  以下情况可能失败或相机被剪枝：
  - 纯色/透明/镜面/严重反光物体；
  - 大面积重复纹理（瓷砖、棋盘格）；
  - 照片之间几乎没有重叠，或物体在画面中太小；
  - 拍摄时变焦、自动曝光剧烈变化、运动模糊。
- 算法会主动剔除与整体模型不一致的相机；状态区的“相机”数量
  可能小于上传照片数，这是正常现象。
- MVS 生成的是 **可见表面** 的网格；完全未拍到的背面不会凭空补全。
- 这是纯 CPU JavaScript 实现，速度和鲁棒性不及 CUDA/COLMAP，
  但无需安装、可离线、完全在浏览器内运行。

## 六、常见问题

**1. 多角度重建提示「没有找到可靠的图像对应关系」**
相邻照片重叠不足或纹理太少。增加照片数量/重叠度，避免纯色背景；
可把“匹配窗口”调到 3–4。

**2. 相机数量明显少于照片数**
部分照片与整体模型不一致（重叠不足、模糊、重复纹理），会被自动剪枝。
换掉这些照片，或增加拍摄数量。

**3. 稠密网格有孔洞/缺失**
增加照片数量和环绕角度，或把稠密精度调到「精细」；
透明/反光表面无法可靠重建。

**4. 导出 GLB 后颜色不对/没有贴图**
网格使用顶点颜色（glTF 的 `COLOR_0`），不是纹理贴图。
在 Blender 中导入 glTF 2.0 后，材质会使用顶点色；不要用 OBJ 导入。

**5. 页面打不开 / 多角度模式没有反应**
请通过 `start.bat` 或 `python -m http.server 8000` 打开。
`file://` 下 ES Module 与本地模型读取都会受限。

**6. iPhone 的 HEIC 照片无法读取**
部分浏览器不能解码 HEIC。请先在系统相册/导出时转换为 JPEG（保留 EXIF 更好），
或使用“兼容性最佳”的相机格式拍摄。

**7. 单张模式很慢**
首次需要初始化 ONNX 推理引擎。支持 WebGPU 的 Chrome/Edge 通常 3–10 秒；
不支持时回退 WASM，首次可能 1–3 分钟。多角度模式不使用神经网络模型，
速度主要取决于照片数量和 MVS 精度。

## 七、测试

需要 Node（测试脚本）和 Python + numpy + Pillow（生成合成数据）。

```bash
# 1. 生成 36 个已知相机位姿的合成视角（输出 tests/synthetic/）
python -I tests/gen_synthetic.py

# 2. PnP / 三角化几何单元测试
node tests/geometry_test.mjs

# 3. SfM + MVS 数值精度测试（相机误差、稀疏点/网格表面误差，写出 recon.ply）
node tests/run_test.mjs standard

# 4. 把重建点云渲染成多角度预览（可选）
python -I tests/render_ply.py

# 5. 无头 Edge 端到端测试（Windows，自动上传 36 张图并截图）
node tests/browser_test.mjs

# 6. 单张模式的浏览器启动检查（加载本地深度模型）
node tests/browser_test.mjs --single

# 7. 快速预览档的数值测试
node tests/run_test.mjs fast
```

参考结果（合成数据，36 视角）：

- SfM：约 30 个有效相机，相机中心误差平均约 1.3% 场景半径，
  旋转误差平均约 1°；
- 稀疏点：到真实表面距离中位数约 0.014；
- 标准 MVS：约 13 万顶点 / 25 万三角面，
  网格顶点到真实表面距离中位数约 0.015、p90 约 0.04；
- 浏览器端到端约 15 s 完成（i5 级 CPU，SfM + 标准 MVS）。

## 八、技术栈

- [Three.js](https://threejs.org/) r169 —— WebGL 渲染、OrbitControls、GLTFExporter
- 单张模式：[Transformers.js](https://github.com/huggingface/transformers.js) v3 +
  ONNX Runtime Web + Depth Anything V2 Small
- 多角度模式：自研纯 JavaScript SfM / MVS
  （ORB、本质矩阵 RANSAC、PnP、LM、Census 平面扫描、TSDF、Marching Tetrahedra）
- 无构建步骤：改完 `index.html` / `js/core/*.js` 刷新即可

## 九、隐私

- 多角度模式：所有图像处理、特征提取、SfM、MVS 均在浏览器本地完成。
- 单张模式：深度模型默认从项目 `models/` 本地加载；若缺失才回退到
  HuggingFace / hf-mirror 在线下载。
- 页面不会把照片上传到任何服务器。
